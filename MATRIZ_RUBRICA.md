# Revisión de cumplimiento frente al Informe Técnico 3

Revisión del prototipo entregado y su suite local. “Implementado” describe una función comprobable en este código; no acredita operación municipal real.

| Área del informe | Estado comprobable | Brecha restante |
| --- | --- | --- |
| Portal ciudadano y panel municipal separados | Implementado como `/app`, `/admin` y cliente de escritorio Windows. `/app` es una PWA React 19/TypeScript estricta (`src/citizen/main.tsx`); `/admin` (`public/municipal.html` + `src/admin/main.ts`) y el backend (`src/server.ts` + `src/repository.ts`) también están migrados a TypeScript estricto. | El uso compartido de datos entre instalaciones requiere publicar una API central con HTTPS sobre base de datos SQL multiusuario. |
| RF-01 a RF-07: reporte guiado, geolocalización, multimedia, duplicados, mapa, detalles y filtros | Implementado localmente: formulario de cuatro pasos, GPS/manual con polígono comunal aproximado (`PUERTO_MONTT_POLYGON` en `src/domain.ts`), foto y video, validación binaria, Haversine, mapas y filtros. | No se ha certificado cada criterio de interacción ni se ha importado un shapefile oficial SUBDERE/IDE del límite comunal. |
| RF-08: procesamiento atómico por lote | Implementado: selección múltiple, asignación masiva; prevalidación, rechazo completo de lote inválido y persistencia por reemplazo de archivo. CP-21 a CP-23. | El archivo local no ofrece garantías ACID equivalentes a un motor SQL frente a fallas físicas del equipo. |
| Cuenta ciudadana, comentarios, apoyos y seguimiento por RUT | Requieren una cuenta autenticada; el servidor toma la identidad desde la sesión y no desde valores enviados por el navegador. La revisión institucional es separada. | El registro local y el chequeo Módulo 11 no equivalen a identidad estatal; la verificación municipal continúa siendo manual. |
| RF-12: notificaciones | Implementado buzón privado persistido, creación al recibir y cambiar estado, y marcado como leído. | Correo SMTP y Web Push no están configurados. |
| RF-10: historial y privacidad pública | Eventos internos conservan notas de gestión; el historial de ciudadano publica textos de estado genéricos para evitar filtrar notas internas. | El JSON local no puede garantizar inmutabilidad forense contra acceso directo al archivo o al equipo. |
| RF-09 a RF-16: gestión, auditoría, cierre, avisos, búsqueda, analítica, calor y RBAC | Implementado localmente en panel TS + backend TS: derivación/transiciones, historial, barrera de cierre (corregido envío de `media` y enlace DOM en `/admin`), seguimiento, indicadores, capa térmica HTML5 Canvas (`src/admin/heatmap.ts`) y controles por roles. | Push/email institucional y autenticación oficial no están conectados; la cola de identidad es revisión manual. |
| Persistencia relacional 3FN y patrón Repository | Implementada detrás de la interfaz `ReportRepository` (`src/repository.ts`) como 10 tablas JSON separadas y enlazadas por ID (`schemaVersion: 3`); conversión automática desde formatos anteriores. | `JsonFileRepository` sigue siendo almacenamiento local por equipo; falta implementar el adaptador PostgreSQL/Supabase con PostGIS/RLS para multiusuario concurrente. |
| RNF-01 a RNF-10, WCAG, OWASP y normativa | Todo el código fuente propio (`src/domain.ts`, `src/repository.ts`, `src/server.ts`, `src/citizen/main.tsx`, `src/admin/main.ts`, `src/admin/heatmap.ts`) compila con `tsc --noEmit` en modo `strict`, `noUncheckedIndexedAccess` y `exactOptionalPropertyTypes`. Controles activos: bcrypt costo 12, límite de intentos, clave HMAC aleatoria por instalación, RBAC por departamento, firma de medios, minimización pública, CORS con allowlist, HMAC de RUT en adhesiones, auditoría, feriados configurables, foco visible, objetivos táctiles de 48 px, movimiento reducido y contraste 4,5:1 probado contra blanco. | Las comprobaciones automatizadas no sustituyen auditoría WCAG AA completa, pentest/OWASP completo ni dictamen jurídico. |
| Electron descargable | Cliente aislado y backend compilado empaquetable con Electron Builder (`npm run desktop:dist`). `npm audit --omit=dev` no reporta vulnerabilidades de runtime. | Sin firma de código institucional; Windows puede advertir que el editor es desconocido. La base instalada es local al usuario. El árbol de herramientas de compilación reporta avisos en dependencias de Electron Builder. |
| CP-01 a CP-31 y regresión | Se ejecutaron 41 pruebas automatizadas: 31 HTTP (`CP-01` a `CP-31`), seis de dominio (incluyendo polígono comunal), dos de accesibilidad/foco, una de aislamiento criptográfico y una de recursos/rutas de caché offline; 41 aprobadas, 0 fallidas. | No reproducen auditoría visual humana ni constituyen auditoría de seguridad independiente. |
| RNF-02: latencia | Medición local reproducible ejecutada sobre `build/server.js`: `npm run perf`, 1.000 registros, 50 clientes paralelos, 200 solicitudes; última ejecución P95 261,1 ms (media 154,3 ms). | Es una medición de este entorno y esa carga. No acredita 1.000 clientes simultáneos ni el entorno/red municipal real. |
| KPI: ART, resolución, adopción y costo | No verificados con datos reales de operación municipal. | Los resultados numéricos del informe previo no se pueden atribuir a este prototipo. |
| ClaveÚnica, SMTP, Web Push, servicio municipal y mapa offline detallado | Pendiente de integración. El PWA sí conserva su shell, bibliotecas y datos públicos recientes; permite ingresar coordenadas manualmente cuando no cargan teselas. | Requiere credenciales y autorización; servidor institucional HTTPS; y proveedor vectorial/raster autoalojado o autorizado para cartografía detallada offline. La política OSM prohíbe precargar y usar offline sus teselas estándar. |

## Resultado de cumplimiento

Se cerraron las brechas técnicas locales posibles: migración completa del backend (`src/server.ts`, `src/repository.ts`) y panel municipal (`src/admin/main.ts`, `src/admin/heatmap.ts`) a **TypeScript estricto**, corrección de los bloqueos en UI/cierre del panel `/admin` (`CP-30`), reemplazo del BBox rectangular por polígono comunal aproximado (`PUERTO_MONTT_POLYGON`, `CP-31`), capa térmica Canvas en analítica y validación de **41/41** pruebas automatizadas más benchmark local (`P95 = 261,1 ms`). Siguen pendientes las integraciones y acreditaciones que dependen de infraestructura, credenciales o auditorías externas: despliegue HTTPS con PostgreSQL/Supabase (PostGIS/RLS), SMTP/Web Push, ClaveÚnica, shapefile oficial comunal, firma digital del `.exe`, auditoría WCAG AA/pentest externa y medición real de KPIs municipales.
